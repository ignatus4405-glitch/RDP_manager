## [1.3.4] - 2026-11-16

### Исправлено
- **Буфер обмена во встроенном RDP — двусторонний и надёжный.** Раньше локальный буфер отправлялся только при инициализации канала CLIPRDR (и мог быть съеден конкуренцией колбэков — флаг `clipboardReady` выставлялся и в remote→local-обработчике), а `navigator.clipboard.readText()` без пользовательского жеста блокировался Chromium — «скопировал в локальном окне → вставил на удалённом» часто не работало вовсе. Теперь локальный буфер поллится раз в 800 мс (во время сессии, через `clipboard.readText()` главного процесса по IPC, с откатом на `navigator.clipboard` в браузере); запись из remote в локальный буфер идёт через `clipboard.writeText()` главного процесса (IPC `clipboard-read`/`clipboard-write` в `client/preload.js`/`client/main.js`); подавление эха remote→local исключает зацикливание.
- **Разрешение встроенного RDP — по доступному пространству и живое.** `desktopSize` запрашивался всегда не больше 1920×1080 и больше не менялся. Теперь размер вычисляется по `.rdp-body` (чётные значения, до 4096×2160), в сеанс добавлено расширение `display_control` (Display Control Virtual Channel), а изменение размера окна с debounce 250 мс шлёт `session.resize(w, h)` — удалённый рабочий стол подстраивается под окно без переподключения. Сервер без Display Control (старые ОС) продолжает работать в фиксированном размере, тогда помогает «⤢ Растянуть».

### Изменено
- Версии пакетов → `1.3.4` (включая fallback в NSIS-скрипте), manifest release-please выровнен.

## [1.3.3] - 2026-11-16

### Исправлено
- **Корневая причина «Не удалось подключиться к RDP-шлюзу» (ProxyConnect): JWT не передавался в `/ws/rdp`.** Шлюз аутентифицирует WebSocket upgrade по запросу `?token=<JWT>` (как и остальной API), а клиент открывал `ws(s)://…/ws/rdp` без токена — сервер отвечал `401 Unauthorized` и рвал сокет, поэтому каждый встроенный RDP-сеанс падал независимо от доступности RDP-узла (в отличие от внешнего RDM). Клиент теперь передаёт токен в URL шлюза; в логах, сообщениях об ошибках и UI токен **не отображается** (показывается только чистый адрес). При отсутствии токена вместо подключения предлагается войти снова.

### Изменено
- Версии пакетов → `1.3.3` (включая fallback в NSIS-скрипте), manifest release-please выровнен.

## [1.3.1] - 2026-11-16

### Исправлено
- **Встроенный RDP: «Failed to fetch» при подключении.** WASM-модуль загружался через `fetch('data:application/wasm;base64,…')`, а наш CSP `connect-src` блокирует `data:` — отсюда TypeError на любом узле. Теперь байты WASM декодируются из data:URL в `ironrdp-entry.mjs` и передаются напрямую в `WebAssembly.instantiate` (сеть не используется). Ошибки подключения переведены в понятные сообщения: `Failed to fetch`/сеть, `401` (сессия истекла), `404` (сервер старее 1.3.0), `5xx` (логи сервера), таймаут/`ECONNREFUSED`/обрыв — с подсказкой, что проверить.

### Изменено
- Версии пакетов → `1.3.1` (включая fallback в NSIS-скрипте), manifest release-please выровнен.

## [1.3.0] - 2026-11-16

### Добавлено
- **Встроенная RDP-сессия прямо в окне приложения — как в Remote Desktop Manager.** RDP больше не требует отдельного окна mstsc/remmina:
  - Клиент: полноэкранный режим `#rdpOverlay` (имя узла, статус, «Во внешнем клиенте», «Отключиться», растяжение canvas). Кнопка «Подключить →» на RDP-карточке открывает форму (логин из карточки, пароль вводится каждый раз и нигде не хранится) → сессия на `<canvas>` через **IronRDP WASM** (CredSSP/NLA): рабочий стол, клавиатура (PS/2-сканкоды, не зависит от раскладки), мышь, колёсико, текстовый буфер обмена в обе стороны. Размер десктопа — по размеру окна (чётные, ≤1920×1080). Ошибки маппятся (`WrongPassword`, `LogonFailure`, `AccessDenied`, `NegotiationFailure`, шлюз недоступен / цель отклонена).
  - Сервер: **RDCleanPath-шлюз** (`server/src/rdp-gateway.js`) на WebSocket `/ws/rdp?token=<JWT>` (новый dependency `ws`): ASN.1 DER поверх WS → TCP/X.224 → TLS (самоподписанные RDP-сертификаты принимаются) → ретрансляция. Allowlist: destination обязан совпадать с RDP-подключением в БД (host:port, дефолт 3389, host без учёта регистра и завершающей точки) — шлюз не открытый релей. Пароли не логируются. Unit-тесты: `server/test/rdp-gateway.test.js` (парсинг destination, allowlist, DER, аутентификация upgrade 401/101).
  - Сборка: `client/renderer/ironrdp-entry.mjs` + `client/scripts/build-ironrdp.js` (esbuild → IIFE, WASM инлайнится как `data:` URL — работает с `file://` в Electron). `vendor/ironrdp/bundle.js` не коммитится, собирается автоматически из `npm run dist` (в CI — тем же шагом). CSP клиента дополнен `wasm-unsafe-eval` и `ws:`/`wss:`.
  - «Во внешнем клиенте» (mstsc / remmina / xfreerdp) по-прежнему доступна из панели встроенной сессии.
  - Требование изменилось: RDP-трафик идёт через сервер — серверу нужен сетевой доступ к RDP-узлам; без него используйте внешний клиент.
  - SEA-сборка и установщики сервера включают шлюз автоматически (esbuild-бандл); проверено на SEA-бинаре (health/login/WS upgrade 101).

- Версии пакетов → `1.3.0` (включая fallback в NSIS-скрипте), manifest release-please выровнен.

## [1.2.1] - 2026-11-16

### Исправлено
- **Windows-установщик сервера: русский текст (финишная страница, MessageBox деинсталляции, имена ярлыков и разделов) отображался «кракозябрами».** Причина: скрипт NSIS был в UTF-8 без BOM — при `Unicode true` makensis читал его в системной ANSI-кодировке (CP1251), а байты UTF-8 декодировались как 1251. Исправлено добавлением UTF-8 BOM (`EF BB BF`) в начало `server/installer/windows/installer.nsi`. Строки, которые приходили из языковых файлов MUI (заголовки страниц), отображались корректно и не были затронуты.
- Релиз v1.2.0: из релиза удалён сырой SEA-бинарник `rdp-manager-server.exe` (88 МБ) — в релизе должны быть только готовые установщики. Паттерны `upload-artifact` и `action-gh-release` в build.yml сужены до имен установщиков, сырой бинарник удаляется после упаковки.

Ставит однофайловый SEA-бинарь сервера в `C:\Program Files\RDP Manager Server\`, регистрирует автозапуск от SYSTEM (Планировщик заданий), запускает сразу, открывает TCP 8720 в брандмауэре, ярлыки «Панель сервера» и удаление, запись в «Установка и удаление программ». Деинсталляция спрашивает про удаление БД (по умолчанию оставить).
  - **Linux**: `RDPManager-Server-<версия>-linux-x64.tar.gz` — `rdp-manager-server` (SEA) + systemd-юнит + `install.sh`/`uninstall.sh`. Ставит в `/opt/rdp-manager-server/`, отдельный пользователь `rdp-manager`, `systemctl enable --now`. `--purge` удаляет и БД.
- **SEA single-executable сборка сервера** (`esbuild` + `postject`, `server/scripts/build-sea.js`): весь сервер (Express, логика, `node:sqlite` — внешние) в одном бинарнике; папка `web/` рядом (веб-панель). База — `data/` рядом с исполняемым файлом (либо `RDP_MANAGER_DATA`). Проверено end-to-end: бинарь ставится, API отвечает, панель раздаётся, сервис стартует под отдельным пользователем.
- CI Build: задача матрицы `Server · Windows (NSIS)` и `Server · Linux (tar.gz + systemd)`; на тегах `v*` серверные установщики публикуются в тот же GitHub Release. Смоук-тест SEA-бинарника в CI (Linux).
- `server/installer/` — NSIS-скрипт, systemd-юнит, install/uninstall скрипты, инструкция по сборке вручную.

### Изменено
- Версии пакетов (root, client, server) → `1.2.0`. Версия сервера в баннере и `/api/health` теперь берётся из `server/package.json` (а не захардкожена).
- Определение «домашнего» каталога приложения (`server/src/paths.js`): env `RDP_MANAGER_HOME` → `web/` рядом с исполняемым файлом (SEA) → dev из репозитория.
