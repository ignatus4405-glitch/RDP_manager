## [1.4.29] - 2026-11-16

### Надёжность
- Для HTTP и HTTPS заданы сроки получения заголовков и полного запроса без таймаута простоя открытых WebSocket.

### Интерфейс
- Ctrl+K переводит фокус на поиск подключений, не перехватывая ввод в открытых сессиях и редакторах.

### Безопасность
- В комплект релиза добавлено формирование CycloneDX SBOM по npm lock-файлу.

## [1.4.28] - 2026-11-16

### Безопасность
- Аудит зависимостей блокирует CI для high/critical; настроены еженедельные проверки Dependabot.

### Сборка
- Публикация релиза выполняется одним заданием после успешной сборки и проверки всех основных артефактов.

## [1.4.27] - 2026-11-16

### Исправлено
- Server Manager определяет адрес и HTTPS веб-панели по конфигурации службы вместо фиксированного HTTP-порта.

### Документация
- Уточнены доступность веб-клиента, версия в README и пути резервного копирования Linux.

### Безопасность
- Сервер требует сменить начальный или сброшенный пароль до доступа к API и RDP; добавлены формы смены в клиенте и веб-панели.

## [1.4.26] - 2026-11-16

### Исправлено
- В установщик включён модуль ipc-access, отсутствие которого препятствовало запуску версии 1.4.25.

## [1.4.25] - 2026-11-16

### Надёжность
- SQLite ожидает освобождения блокировки до пяти секунд; существующий режим WAL сохранён.

### Безопасность
- Управление службой через IPC разрешено только основному фрейму окна Server Manager.
- Для RDP-шлюза используются одноразовые тикеты вместо JWT в URL; клиент и сервер необходимо обновить вместе.
- Добавлено ограничение неудачных попыток входа по логину и IP на одном серверном процессе.
- Сервер отправляет базовые защитные заголовки, HSTS включается только при прямом HTTPS.
- В журнал запросов API больше не записывается строка запроса, которая может содержать секреты.
- Проверка паролей выполняется асинхронно с ограниченной очередью; неизвестные логины проходят фиктивную проверку.
- Актуальная роль и статус пользователя проверяются при запросах и подключении к RDP-шлюзу; токены отзываются при смене полномочий и паролей.
- При изменении порта карточки её общий сохранённый пароль удаляется.
- Поиск подключений и документов не зависит от регистра кириллических букв.

## [1.4.14] - 2026-11-16

### Изменено
- SFTP: двухпанельный файловый менеджер с локальным и удалённым каталогами, навигацией и передачей выбранных файлов. Требуется проверка на Windows и реальном SFTP-сервере.

## [1.4.13] - 2026-11-16

### Добавлено
- Экспериментальные изолированные веб-приложения с заполнением простых HTTPS-форм. Сложные формы, SSO и MFA могут требовать ручного входа.
- Экспериментальные встроенные SSH-терминал и SFTP с ручной проверкой отпечатка ключа сервера перед передачей пароля. Реальные Windows-сессии и SFTP требуют проверки.
- Серверное шифрованное хранилище паролей подключений и поддержка HTTPS; в карточке RDP можно указать пароль. Удалённая передача пароля требует HTTPS. Ключ хранилища необходимо сохранять вместе с резервной копией базы; все активные сотрудники имеют доступ к паролям подключений.
- Домен в карточке RDP передаётся во встроенный клиент; для внешнего клиента используется имя в формате DOMAIN\user. Проверка подключения к домену на реальном RDP-сервере необходима.

## [1.4.11] - 2026-11-16

### Добавлено
- Экспериментальный файловый буфер RustDesk для Windows: файлы и папки предлагаются через OLE, содержимое передаётся при вставке. Нужна проверка на реальном Windows/RustDesk-сеансе; сессия должна оставаться открытой.
- Сервер ID и публичный ключ RustDesk задаются в карточке подключения. Существующие базы обновляются автоматически; для старых карточек сохранён резервный вариант локальных настроек.

### Ограничения
- Файловый буфер ограничен 4096 объектами и относительными путями длиной до 259 символов, символические ссылки не передаются. HTML и изображения не поддерживаются.

## [1.3.4] - 2026-11-16

### Исправлено
- **Буфер обмена во встроенном RDP — двусторонний и надёжный.** Раньше локальный буфер отправлялся только при инициализации канала CLIPRDR (и мог быть съеден конкуренцией колбэков — флаг `clipboardReady` выставлялся и в remote→local-обработчике), а `navigator.clipboard.readText()` без пользовательского жеста блокировался Chromium — «скопировал в локальном окне → вставил на удалённом» часто не работало вовсе. Теперь локальный буфер поллится раз в 800 мс (во время сессии, через `clipboard.readText()` главного процесса по IPC, с откатом на `navigator.clipboard` в браузере); запись из remote в локальный буфер идёт через `clipboard.writeText()` главного процесса (IPC `clipboard-read`/`clipboard-write` в `client/preload.js`/`client/main.js`); подавление эха remote→local исключает зацикливание.

Теперь размер вычисляется по `.rdp-body` (чётные значения, до 4096×2160), в сеанс добавлено расширение `display_control` (Display Control Virtual Channel), а изменение размера окна с debounce 250 мс шлёт `session.resize(w, h)` — удалённый рабочий стол подстраивается под окно без переподключения. Сервер без Display Control (старые ОС) продолжает работать в фиксированном размере, тогда помогает «⤢ Растянуть».

## [1.3.3] - 2026-11-16

### Исправлено
- **Корневая причина «Не удалось подключиться к RDP-шлюзу» (ProxyConnect): JWT не передавался в `/ws/rdp`.** Шлюз аутентифицирует WebSocket upgrade по запросу `?token=<JWT>` (как и остальной API), а клиент открывал `ws(s)://…/ws/rdp` без токена — сервер отвечал `401 Unauthorized` и рвал сокет, поэтому каждый встроенный RDP-сеанс падал независимо от доступности RDP-узла (в отличие от внешнего RDM). Клиент теперь передаёт токен в URL шлюза; в логах, сообщениях об ошибках и UI токен **не отображается** (показывается только чистый адрес). При отсутствии токена вместо подключения предлагается войти снова.

## [1.3.1] - 2026-11-16

### Исправлено
- **Встроенный RDP: «Failed to fetch» при подключении.** WASM-модуль загружался через `fetch('data:application/wasm;base64,…')`, а наш CSP `connect-src` блокирует `data:` — отсюда TypeError на любом узле. Теперь байты WASM декодируются из data:URL в `ironrdp-entry.mjs` и передаются напрямую в `WebAssembly.instantiate` (сеть не используется). Ошибки подключения переведены в понятные сообщения: `Failed to fetch`/сеть, `401` (сессия истекла), `404` (сервер старее 1.3.0), `5xx` (логи сервера), таймаут/`ECONNREFUSED`/обрыв — с подсказкой, что проверить.
