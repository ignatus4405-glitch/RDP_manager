## [Unreleased]

### Добавлено
- **Встроенная RDP-сессия прямо в окне приложения — как в Remote Desktop Manager.** RDP больше не требует отдельного окна mstsc/remmina:
  - Клиент: полноэкранный режим `#rdpOverlay` (имя узла, статус, «Во внешнем клиенте», «Отключиться», растяжение canvas). Кнопка «Подключить →» на RDP-карточке открывает форму (логин из карточки, пароль вводится каждый раз и нигде не хранится) → сессия на `<canvas>` через **IronRDP WASM** (CredSSP/NLA): рабочий стол, клавиатура (PS/2-сканкоды, не зависит от раскладки), мышь, колёсико, текстовый буфер обмена в обе стороны. Размер десктопа — по размеру окна (чётные, ≤1920×1080). Ошибки маппятся (`WrongPassword`, `LogonFailure`, `AccessDenied`, `NegotiationFailure`, шлюз недоступен / цель отклонена).
  - Сервер: **RDCleanPath-шлюз** (`server/src/rdp-gateway.js`) на WebSocket `/ws/rdp?token=<JWT>` (новый dependency `ws`): ASN.1 DER поверх WS → TCP/X.224 → TLS (самоподписанные RDP-сертификаты принимаются) → ретрансляция. Allowlist: destination обязан совпадать с RDP-подключением в БД (host:port, дефолт 3389, host без учёта регистра и завершающей точки) — шлюз не открытый релей. Пароли не логируются. Unit-тесты: `server/test/rdp-gateway.test.js` (парсинг destination, allowlist, DER, аутентификация upgrade 401/101).
  - Сборка: `client/renderer/ironrdp-entry.mjs` + `client/scripts/build-ironrdp.js` (esbuild → IIFE, WASM инлайнится как `data:` URL — работает с `file://` в Electron). `vendor/ironrdp/bundle.js` не коммитится, собирается автоматически из `npm run dist` (в CI — тем же шагом). CSP клиента дополнен `wasm-unsafe-eval` и `ws:`/`wss:`.
  - «Во внешнем клиенте» (mstsc / remmina / xfreerdp) по-прежнему доступна из панели встроенной сессии.
  - Требование изменилось: RDP-трафик идёт через сервер — серверу нужен сетевой доступ к RDP-узлам; без него используйте внешний клиент.
  - SEA-сборка и установщики сервера включают шлюз автоматически (esbuild-бандл); проверено на SEA-бинаре (health/login/WS upgrade 101).

## [1.2.1] - 2026-11-16

### Исправлено
- **Windows-установщик сервера: русский текст (финишная страница, MessageBox деинсталляции, имена ярлыков и разделов) отображался «кракозябрами».** Причина: скрипт NSIS был в UTF-8 без BOM — при `Unicode true` makensis читал его в системной ANSI-кодировке (CP1251), а байты UTF-8 декодировались как 1251. Исправлено добавлением UTF-8 BOM (`EF BB BF`) в начало `server/installer/windows/installer.nsi`. Строки, которые приходили из языковых файлов MUI (заголовки страниц), отображались корректно и не были затронуты.
- Релиз v1.2.0: из релиза удалён сырой SEA-бинарник `rdp-manager-server.exe` (88 МБ) — в релизе должны быть только готовые установщики. Паттерны `upload-artifact` и `action-gh-release` в build.yml сужены до имен установщиков, сырой бинарник удаляется после упаковки.

### Изменено
- Версии пакетов → `1.2.1` (включая fallback в NSIS-скрипте), manifest release-please выровнен.

## [1.2.0] - 2026-11-16

### Добавлено
- **Отдельный установщик серверной части** (клиент и сервер — теперь разные артефакты релиза):
  - **Windows**: `RDPManager-Server-Setup-<версия>.exe` (NSIS). Ставит однофайловый SEA-бинарь сервера в `C:\Program Files\RDP Manager Server\`, регистрирует автозапуск от SYSTEM (Планировщик заданий), запускает сразу, открывает TCP 8720 в брандмауэре, ярлыки «Панель сервера» и удаление, запись в «Установка и удаление программ». Деинсталляция спрашивает про удаление БД (по умолчанию оставить).
  - **Linux**: `RDPManager-Server-<версия>-linux-x64.tar.gz` — `rdp-manager-server` (SEA) + systemd-юнит + `install.sh`/`uninstall.sh`. Ставит в `/opt/rdp-manager-server/`, отдельный пользователь `rdp-manager`, `systemctl enable --now`. `--purge` удаляет и БД.
- **SEA single-executable сборка сервера** (`esbuild` + `postject`, `server/scripts/build-sea.js`): весь сервер (Express, логика, `node:sqlite` — внешние) в одном бинарнике; папка `web/` рядом (веб-панель). База — `data/` рядом с исполняемым файлом (либо `RDP_MANAGER_DATA`). Проверено end-to-end: бинарь ставится, API отвечает, панель раздаётся, сервис стартует под отдельным пользователем.
- CI Build: задача матрицы `Server · Windows (NSIS)` и `Server · Linux (tar.gz + systemd)`; на тегах `v*` серверные установщики публикуются в тот же GitHub Release. Смоук-тест SEA-бинарника в CI (Linux).
- `server/installer/` — NSIS-скрипт, systemd-юнит, install/uninstall скрипты, инструкция по сборке вручную.

### Изменено
- Версии пакетов (root, client, server) → `1.2.0`. Версия сервера в баннере и `/api/health` теперь берётся из `server/package.json` (а не захардкожена).
- Определение «домашнего» каталога приложения (`server/src/paths.js`): env `RDP_MANAGER_HOME` → `web/` рядом с исполняемым файлом (SEA) → dev из репозитория.

## [1.1.1] - 2026-11-16

### Исправлено
- **Автообновление клиента**: секция `publish` (provider github) остаётся в конфиге electron-builder — именно она вшивает в сборку `app-update.yml` (адрес репозитория для electron-updater). Удаление секции чинило сборку, но ломало автообновление в рантайме; теперь сборка передаёт `GH_TOKEN` (его наличие обязательно даже при `--publish never`), а публикацией релиза по-прежнему занимается `softprops/action-gh-release`. В Build добавлен шаг проверки, что `app-update.yml` встроен в `*-unpacked/resources/` — иначе джоб падает.
- **Внимание: установленный v1.1.0 собран без `app-update.yml` и не умеет автообновляться** — v1.1.1 ставится одноразово вручную, дальше обновления пойдут автоматически.
- `electron` перенесён из `dependencies` в `devDependencies` с точной версией `45.3.3` (билд падал мгновенно: «only allowed in devDependencies» / «version is a range»). Добавлены `author`, `license`.
- CI Build: публикация релиза перенесена на `softprops/action-gh-release` (нет гонки матрицы Windows/Linux); `latest(-linux).yml` генерируется отдельным скриптом `client/scripts/make-latest-yml.js` (sha512 + size).
- Смоук-тест сервера: на Windows ждём выхода дочернего процесса перед удалением временной папки SQLite (EPERM/EBUSY); при падении сервера его лог выводится в ошибку.
- Build запускается на каждый push в любую ветку, а не только в `main` и теги.

## [1.1.0] - 2026-11-16

### Добавлено
- **CI** (`.github/workflows/ci.yml`): синтаксическая проверка всех JS, смоук-тесты сервера (`node:test`), проверка доступности electron-builder — на каждый push и PR.
- **Автосборка** (`.github/workflows/build.yml`): сборка установщиков Windows (NSIS) и Linux (AppImage) на push в `main`, на теги `v*`, на PR и вручную. Артефакты сохраняются (14 дней).
- **Автопубликация**: на теге `v*` установщики и `latest.yml` публикуются в GitHub Release (`electron-builder --publish always`).
- **Автоматическое версионирование** (`.github/workflows/release.yml`, release-please): Release PR с bump версии и этим changelog по Conventional Commits; мерж PR создаёт тег `vX.Y.Z`.
- **Клиент: уведомление о новой версии**. Собранное приложение при старте и раз в 6 часов проверяет GitHub Releases (electron-updater, тихая загрузка, установка при выходе / по кнопке «Установить и перезапустить»). В профиле — кнопка «Проверить обновления» и номер версии. В dev-режиме и в браузере проверка идёт через публичное Releases API GitHub с предложением скачать новую версию.
- **Смоук-тест сервера** (`server/test/smoke.test.js`): здоровье API, логин, CRUD, права доступа, смена пароля.
- Документация: `CHANGELOG.md`, `CONTRIBUTING.md`, `AGENTS.md` (инструкция для продолжения работы любым агентом), раздел про автосборку в `README.md`.

### Изменено
- Версии пакетов (`root`, `client`, `server`) подняты до `1.1.0`.
- Клиент переведён на компонентную версионную схему артефактов: `RDPManager-Setup-1.1.0.exe`, `RDPManager-1.1.0.AppImage`.
- `electron-builder` обновлён до `^26.18.0` (исправления предупреждений безопасности), `electron` — до `^45.3.3`.

### Технические заметки
- `electron-updater` публикует и потребляет `latest.yml` из GitHub Releases; требуется `contents: write` у `GITHUB_TOKEN` (выдан в workflows).
- Автообновление в приватном репозитории не работает анонимно — см. CONTRIBUTING.md, раздел «Приватный репозиторий».

## [1.0.0] - 2026-11-16

### Добавлено
- **Сервер** (`server/`): Node.js + Express + SQLite (`node:sqlite`).
  - REST API: авторизация JWT (HMAC-SHA256, 12 ч), роли `admin` / `employee`.
  - База подключений RDP / AnyDesk / RustDesk: категории, теги, полнотекстовый поиск, фильтры, счётчики.
  - Документация (Markdown) с разделами и поиском.
  - Управление учётными записями: создание администраторов и сотрудников, сброс пароля, отключение, удаление; защита от удаления/отключения собственной записи.
  - Пароли: scrypt + соль; принудительная смена при первом входе (поле `must_change_password`).
  - Встроенная веб-панель администратора (`/`) и веб-режим клиента (`/app/`).
  - Первичное наполнение: `admin` / `admin123` (смена обязательна).
- **Десктоп-клиент** (`client/`): Electron.
  - Вход под своей учётной записью, адрес сервера настраивается и сохраняется.
  - Поиск и фильтрация подключений, запуск в один клик: Windows — `mstsc` / AnyDesk / RustDesk; Linux — FreeRDP / Remmina (иначе protocol-handler).
  - Документация внутри приложения (Markdown-просмотр, свои стили).
  - Разделы «Пользователи» (только администратор) и «Профиль» (смена пароля).
