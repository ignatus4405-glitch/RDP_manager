# Установщики RDP Manager Server

## Windows — единый `RDPManager-Setup-<версия>.exe`

Отдельный Windows-установщик сервера больше не выпускается. Сервер входит в общий NSIS-установщик клиента; при запуске от администратора выберите один вариант:

1. **Только десктоп-клиент**.
2. **Серверная служба + графическое управление**.
3. **Клиент и сервер**.

Перед установкой выберите компоненты и, для сервера, папку базы и ключа (по умолчанию `%ProgramData%\RDP Manager Server\data`). Выбор сохраняется для обновлений, в том числе тихих. При смене папки существующие данные копируются в новую, исходная копия остаётся на месте; папка назначения не должна содержать другую базу. Убедитесь, что выбранная папка доступна службе LocalSystem и защищена от доступа посторонних пользователей. Установка сервера:

- устанавливает SEA-бинарь и веб-панель в подпапку `server` рядом с Electron-приложением;
- регистрирует WinSW-службу `RDPManagerServer` (учётная запись `LocalSystem`), автоматический запуск при старте Windows и перезапуск после ошибки;
- создаёт правило входящего брандмауэра для TCP 8720 и запускает службу;
- хранит базу/секрет в выбранной папке, журнал — в `%ProgramData%\RDP Manager Server\logs\server.log` (ротация до 5 файлов); stdout/stderr WinSW также ротируются;
- добавляет ярлык **«Управление сервером»**: окно показывает статус и лог, даёт управлять службой (с запросом UAC), открывать веб-панель и проверять GitHub Releases; закрытие окна скрывает его в системный трей;
- при переходе со старого отдельного установщика останавливает его задачу Планировщика, копирует БД и ключ из `C:\Program Files\RDP Manager Server\data` в выбранную папку (если там ещё нет базы) и удаляет старые исполняемые файлы; при выборе «только клиент» старая служба также снимается, а данные сохраняются для возможной последующей установки сервера.

Обновления проверяются и загружаются в клиенте и в менеджере сервера. После загрузки нажмите «Установить обновление» и подтвердите действие: приложение закроется, служба временно остановится, затем единый установщик обновит выбранные компоненты. Перед установкой сохраните работу и закройте другие окна RDP Manager; Windows может запросить права администратора. При ошибке загрузки можно открыть страницу релиза и установить обновление вручную. Автообновление не устанавливается без подтверждения при обычном выходе из программы.

Обычному пользователю выдаётся право чтения каталога логов, чтобы GUI мог показывать журнал. Права на выбранную папку базы наследуются от её расположения; при необходимости ограничьте их для системы и администраторов. При обычном удалении служба/ярлыки/правило брандмауэра удаляются, база и логи сохраняются; установщик спрашивает перед удалением известных файлов базы и логов, не удаляя другие файлы в выбранной папке.

Сборка Windows выполняется в job клиента `.github/workflows/build.yml`:

```powershell
npm ci
npm run build:sea --workspace server
npm run stage:windows-server --workspace client
npm run dist --workspace client
```

Скрипт `client/scripts/stage-windows-server.js` скачивает WinSW **v2.13.0** с официального GitHub Release, проверяет закреплённый SHA-256 и кладёт комплект в `client/build/server-payload/`. NSIS-страница и действия компонентов описаны в `client/build/installer.nsh`; сервис — в `server/installer/windows/RDPManagerServer.xml`. Сборка требует Windows: SEA нужно собирать под целевую ОС.

## Linux — `RDPManager-Server-<версия>-linux-x64.tar.gz`

```bash
tar -xzf RDPManager-Server-<версия>-linux-x64.tar.gz
cd rdp-manager-server
sudo bash install.sh
```

`install.sh`:
- ставит в `/opt/rdp-manager-server/`;
- создаёт системного пользователя `rdp-manager` (без логина) — сервер работает не от root;
- создаёт systemd-юнит `/etc/systemd/system/rdp-manager-server.service`, включает и запускает его;
- печатает адрес панели и подсказки (`journalctl -u rdp-manager-server -f`).

Удаление без потери БД: `sudo bash uninstall.sh`; полное удаление (с БД): `sudo bash uninstall.sh --purge`.
> Если нужен другой порт: `sudo systemctl edit rdp-manager-server` → `[Service]` → `Environment=RDP_MANAGER_PORT=9000`, затем `daemon-reload && restart`.

## Общая сборка SEA

```bash
npm ci
npm run build:sea --workspace server
```

`esbuild` объединяет исходники и зависимости в SEA-бинарь. Для Windows и Linux бинарники собираются на соответствующих runner'ах GitHub Actions. Windows-пayload включается в общий Electron NSIS-инсталлятор; Linux-пакет остаётся отдельным tar.gz с systemd-скриптами.
