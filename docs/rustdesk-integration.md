# Экспериментальный встроенный RustDesk

При создании или редактировании карточки RustDesk укажите сервер ID из настроек
RustDesk и **публичный** ключ `id_ed25519.pub`; ID устройства указывается в
поле адреса. При открытии сеанса эти настройки берутся из карточки. Приватный ключ `id_ed25519`,
пароли и токены передавать разработчику нельзя; пароль удалённого устройства
вводится для сеанса и не сохраняется в настройках.

Если WSS-шлюза нет, клиент использует WebSocket-порт сервера ID (обычно
21118; порт ID плюс 2) и WebSocket-порт relay (обычно 21119; порт relay плюс
2). Оба порта должны быть доступны с компьютера клиента. Relay выбирается по
ответу сервера ID. Если используется нестандартная схема портов или отдельный
relay, совместимость необходимо проверить. Настройки сервера и публичный ключ
хранятся на сервере RDP Manager в карточке подключения. Для старых карточек
без этих настроек используется ранее сохранённая локальная конфигурация, если
она есть; её можно перенести в карточку вручную.

Транспорт использует **ws:// без TLS**: адреса, ID и другие метаданные
соединения могут быть видны сети. Протокол библиотеки rdweb предусматривает
проверку подписей и сквозное шифрование содержимого; правильный публичный ключ
сервера нужно получить по доверенному каналу. Приложение не отключает проверку
подлинности. Независимого аудита библиотеки или проверки подключения к вашему
серверу пока не проводилось. В браузерном режиме прямой WS отключён; для
HTTPS-страницы необходим WSS-шлюз и отдельная интеграция.

В этой экспериментальной реализации текстовый буфер синхронизируется в обе
стороны. При нескольких экранах в верхней панели появляется выбор монитора.
Для Windows-клиента добавлен экспериментальный файловый буфер: метаданные
публикуются через OLE, содержимое запрашивается при вставке. Передача использует
сообщения Cliprdr RustDesk внутри сеанса; нужны разрешения на буфер и передачу
файлов на удалённом устройстве. Дескрипторы содержат запрос отображения
прогресса Проводника; локальный Windows OLE-источник допускает асинхронную
вставку. Окно управляется самим Проводником: его появление зависит от Windows,
удалённого RustDesk и приложения назначения, и не гарантируется для коротких
операций. Сессия должна оставаться открытой. Необходимо проверить на реальном Windows/RustDesk копирование в обе стороны, вставку
клавиатурой и мышью, папки, отмену, смену буфера и переподключение. На других
клиентских ОС файловый буфер не включён. Сейчас ограничены число объектов в
одном списке (4096) и длина относительного пути (259 символов); символические
ссылки не передаются. HTML и изображения не поддерживаются. Не заявляется полная
замена клиента RustDesk. Серверы с обязательной авторизацией клиента (`MUST_LOGIN`) пока не
поддерживаются. AnyDesk в эту работу не входит.

Используется [rdweb](https://github.com/bropines/rdweb), MIT, фиксированный
commit указан в `client/vendor/rdweb/PROVENANCE.md`. Локальные тесты не заменяют
проверку совместимости и безопасности протокола в реальной сети.
