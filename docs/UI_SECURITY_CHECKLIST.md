# Чек-лист плана интерфейса и безопасности

Источник: `UI_AND_SECURITY_PLAN.txt`, составленный для версии 1.4.14. Состояние сверено с релизом 1.4.28 и текущими изменениями (2026-11-16). Это **промежуточный** чек-лист: весь план ещё не реализован. Изменения SBOM, Ctrl+K и HTTP-таймаутов ещё не выпущены.

Обозначения: **[x]** — реализована конкретная описанная часть; **[~]** — частично или требуется проверка; **[ ]** — не реализовано. Даже для отмеченных пунктов автоматические тесты не заменяют проверку установленной программы на Windows.

## Безопасность (S)

- [~] **S-01** Роль, статус и версия токена проверяются по БД; токены отзываются при смене полномочий и пароля. TTL остаётся 12 часов по умолчанию; уже открытые RDP-сеансы не закрываются автоматически.
- [~] **S-02** Есть ограничение попыток в памяти одного процесса и одинаковая ошибка входа. Сервер требует сменить начальный/сброшенный пароль до доступа к API и RDP; добавлены формы клиента и веб-панели. Оповещения администратора и Windows GUI-проверка ещё нужны. Общий IP может временно затронуть нескольких пользователей; счётчики сбрасываются при перезапуске.
- [~] **S-03** Запросы API используют асинхронный scrypt с ограниченным числом задач и очередью; health проверен при 20 запросах. Первичное создание администратора при старте остаётся синхронным; защита не исключает все виды DoS.
- [~] **S-04** Одноразовые тикеты на 30 секунд привязаны к пользователю, карточке и видимому IP; тестируются повтор, истечение и неверная цель. Проверка Origin и реальная Windows/RDP-проверка остаются. Тикеты хранятся в памяти одного процесса; для балансировки нужна привязка к серверу и одинаковый видимый IP.
- [~] **S-05** Прямой HTTPS/WSS и базовые заголовки реализованы, HSTS — при прямом HTTPS. Полный CSP, предупреждение HTTP и изменение сетевого значения по умолчанию не завершены; сервер по умолчанию слушает `0.0.0.0`.
- [ ] **S-06** Проверка сертификата RDP-узла: выбран вариант с подтверждением и закреплением отпечатка; реализация отсутствует. Текущий шлюз не обеспечивает строгую проверку сертификата RDP.
- [ ] **S-07** Убрать `admin/admin123`: выбран мастер первого запуска; ещё не реализован. До исправления не разворачивать сервер в недоверенной сети, немедленно сменить начальный пароль и защитить доступ к серверу.
- [~] **S-08** Отзыв всех токенов пользователя при изменениях реализован; отдельный logout на сервере, refresh, список сеансов, безопасное запоминание и блокировка не реализованы.
- [~] **S-09** IPC управления службой проверяет окно и основной фрейм; отдельные preload, проверка остальных IPC и sandbox для всех окон не завершены.
- [~] **S-10** Query API не пишется в журнал; полный аудит журналов, исключение чувствительных данных во всех ошибках и настройки хранения остаются.
- [ ] **S-11** Парольная политика из плана (12 символов, словарь и индикатор) не реализована; текущий минимум — 6 символов. Новый пароль должен отличаться от текущего.
- [~] **S-12** Для неизвестного логина выполняется фиктивный scrypt, сообщение входа единое; идентичность времени ответа не гарантируется.
- [~] **S-13** Ключи токенов и паролей подключений разные; создание и кэширование, Windows ACL и процедура безопасной ротации требуют дальнейшей проверки.
- [~] **S-14** Ограничение общего доступа к паролям задокументировано; разграничения по карточкам и аудита выдачи нет. Все активные сотрудники после смены начального пароля могут получить общий пароль карточки.
- [ ] **S-15** ACL и безопасное сохранение данных при удалении. Выбрано сохранять базу и ключи; проверка пути внутри каталога программы и изменение деинсталлятора ещё не выполнены. До удаления сделайте резервную копию базы и обоих ключей.
- [~] **S-16** Общий лимит JSON и ограничение входа существуют. Для HTTP/HTTPS заголовки ограничены 30 с, полный запрос — 120 с; проверка просроченных соединений раз в 5 с, без таймаута простоя установленных WebSocket. Есть тесты незавершённых запросов и открытого WebSocket. Отдельные лимиты документов, общий IP rate limit и квоты WebSocket не завершены; устойчивость к массовой атаке не подтверждена.
- [~] **S-17** CI блокирует high/critical в полном npm audit и выводит moderate; настроен еженедельный Dependabot для npm workspaces и GitHub Actions, Electron закреплён точной версией. Dependabot создал PR в GitHub. Добавлено формирование CycloneDX SBOM по npm lock-файлу при публикации релиза; фактическую публикацию SBOM ещё проверить. SBOM включает зависимости сборки и не описывает полный состав бинарников, нативные и внешние компоненты. При недоступности npm audit CI также завершится ошибкой.
- [~] **S-18** WAL и `busy_timeout=5000` включены и проверены тестом. Конкурентная нагрузка, регулярный бэкап и восстановление требуют практической проверки.
- [ ] **S-19** Единый формат ошибок и полная проверка отсутствия внутренних путей.
- [ ] **S-20** Аудит действий и его просмотр/экспорт.

## Проверки этого этапа

- Автоматические тесты API проверяют блокировку нового администратора и сотрудника до смены пароля, сброшенный пароль, выдачу RDP-тикета и последующий доступ.
- Отдельные тесты проверяют логику обязательных форм клиента и серверной веб-панели, а также отказ RDP upgrade при обязательной смене пароля.
- Тесты разбора XML Server Manager покрывают порт, HTTPS, IPv6 и неверные настройки; реальную конфигурацию службы на Windows нужно проверить.
- `npm run check` и `npm test` прошли на Linux; Windows-специфичные тесты были пропущены. GUI, реальный RDP, обновление Windows-службы и восстановление бэкапа не проверялись.

- D-07: YAML разобран, структурный тест единого задания публикации прошёл; `npm run check` и `npm test` прошли (сервер 20/20, клиент 85/90, 5 Windows-тестов пропущены). Новый путь публикации успешно выполнен для v1.4.28.

- S-17: локальный `npm audit --audit-level=high` прошёл с 6 moderate в цепочке инструментов сборки; новых high/critical не обнаружено на момент проверки. Dependabot создал PR после слияния конфигурации. После изменений S-17 `npm run check` и `npm test` прошли: сервер 20/20, клиент 87/92 (5 Windows-тестов пропущены).

- S-17 SBOM: CycloneDX JSON формируется из npm lock-файла с зависимостями всех workspaces и сборочными зависимостями; валидация генератором и тест наличия основных пакетов выполняются локально. После `npm ci` прошли `npm run check` и `npm test` (сервер 20/20, клиент 88/93, 5 Windows-тестов пропущены); npm audit high+ прошёл, остаются 6 moderate. Добавление в реальный релиз ещё не проверено.

- U-16: тесты проверяют Ctrl+K при кириллической раскладке и отказ обработки в сессиях, диалогах, полях ввода и на экране входа. `npm run check` и `npm test` прошли: сервер 20/20, клиент 90/95 (5 Windows-тестов пропущены). Реальный GUI и передача сочетаний в RDP/SSH/RustDesk на Windows ещё не проверены.

- S-16: тесты HTTP-парсера используют сокращённые сроки, проверяют ответ 408 при неполных заголовках и теле, обычный запрос и сохранение установленного WebSocket при простое. `npm run check` и `npm test` прошли: сервер 23/23, клиент 90/95 (5 Windows-тестов пропущены). Реальная нагрузка и работа RDP не проверены.
